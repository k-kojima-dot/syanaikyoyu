タブが増え続けたのは、開けたのに「開けなかった」と判定していたからです

システムの問題でした。原因は2つが重なったもので、片方だけでは表面化しません。山本さんの端末だけで起きたのにも理由があります。修正は本番反映済みです。

原因

01タブは開いているのに、開けなかったことにしていた
const w = window.open(url, "_blank", "noopener"); if (w) { await consume(call.id); // ← ここに来ない } else { setPending(call); // 「ブロックされた」扱い }

noopener を付けると、実際にタブが開けても仕様上 null が返ります。コードはこれを「ポップアップがブロックされた」と読み違えていたため、タブは開いているのに着信の消し込みを行いませんでした。着信は未処理のまま残り続けます。

02開いた先のタブが、また次のタブを開いた

自動で開くのは /dashboard/cases/new。これも /dashboard の配下なので、開いた先のタブでも着信リスナーが動き出します。「もう開いた着信」の記録はタブの中だけに持っていたので、新しいタブでは空。未処理の着信を見つけて、また開く——の繰り返しでした。

受付画面└→新規案件 #1
└→新規案件 #2
└→新規案件 #3
└→…消し込まれるまで止まらない

実際の記録

該当の着信（発信者 09033797768）を追いました。

時刻内線消し込み意味
15:30:48813未処理須沢さんの席。取らなかった
15:31:03806未処理同上
15:31:0481415:40:00山本さんの席。消し込みまで9分

着信は10分前まで遡って拾う仕様です。消し込みが9分間行われなかったため、その間ずっと同じ着信が「未処理」として返り続け、開いたタブが次々と新しいタブを開いていました。15:40の消し込み（おそらくバナーをタップした操作）で止まっています。

なぜ山本さんだけだったか

原因 01 は「開けたのに開けなかったことにする」不具合なので、そもそもポップアップが開ける端末でしか表面化しません。他のオペレーターの端末ではブラウザがポップアップをブロックしていて、その場合はバナーが出てタップ → その操作でちゃんと消し込みが走るため、連鎖が起きませんでした。ブラウザ側の設定なので、ログアウトして入り直しても直らなかったのはそのためです。

直した内容

本番反映済み（buildId b_lZw-eObmRbxkPBNtqyK）。

  • noopener を外しました。開けたかどうかを返り値で正しく判定できるようになり、開いたら必ず消し込みが走ります。開き先は同じサイト内なので noopener は不要です。
  • 「自動で開いた着信」をブラウザ全体で共有するようにしました。これまではタブの中だけの記録だったため、新しいタブでは空でした。開く前に記録するので、消し込みが失敗しても1つの着信につきタブは1枚までです。
