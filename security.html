02 何が危なくて、どう直したか

Broken Access Control / IDOR

問題：受付/管理用のAPIが「ログイン済みか」だけを見て「役割」を確認していませんでした。そのため最下位権限の作業員(WORKER)アカウントでも、直接APIを叩けば顧客の氏名・住所・電話番号を全件閲覧でき、案件の改変までできる状態でした。

作業員アカウント → オフィス用API → 顧客PII全件が丸見え
修正後 → 役割チェック isOfficeSideRole() → 管理者/オペレーターのみ許可・作業員は403拒否

封鎖したエンドポイント

  • GET / POST /api/cases — 案件一覧・新規作成
  • GET / PUT /api/cases/[id] — 案件詳細・更新（削除は既に管理者限定）
  • POST /api/cases/[id]/claim — 着信案件の担当引き当て
  • GET /api/dashboard/document-logs — 会社横断の帳票・請求履歴

作業員の画面は /api/worker/* しか使っていないため、今回の変更による現場への影響はありません（全呼び出し元が管理画面配下であることを確認済み）。

05 来月以降の候補（重大度順・毎月1件ずつ）

  1. 依存ライブラリの脆弱性更新 High〜Critical
    認証ライブラリ等に既知の脆弱性。修正は大型アップデートを伴い要検証。
  2. CSP（コンテンツセキュリティポリシー）追加 Medium
    他のヘッダーは設定済み。XSS対策の最後の一枚。まず監視モードから段階導入。
  3. 監査ログの導入 Medium
    「誰がいつ顧客情報を見た/変えた」の記録がない。個情法対応としても重要。
  4. AIへの個人情報送信の整理 Medium
    通話文字起こしをGeminiへ送る箇所。同意・契約面の整理。
  5. マスタAPI2件の認証追加 Low
    今月の点検が検出。個人情報なしで軽微だが、整合のため対応推奨。
次の一手のおすすめ： マスタAPI2件（軽微）は放置すると毎月CIが警告を出し続けるため、早めに「認証追加」か「意図的公開として明示」のどちらかを決めておくと、月次の警告がクリーンに保てます。来月の「1件」は上位の依存脆弱性の更新かCSP導入が有力候補です。
